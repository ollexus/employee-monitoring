# Мониторинг рабочей активности — клиент-серверное приложение

Учебный проект: отображение текущей трудовой активности сотрудников организации.
Агент на каждом рабочем месте передаёт серверу состояние рабочей станции и снимки экрана,
оператор видит всех подключённых сотрудников в веб-панели.

```
   Рабочее место (Windows)                        Сервер (Windows / Linux)
 ┌──────────────────────────────────┐        ┌────────────────────────────────────┐
 │ EmployeeMonitoring.Client.exe     │  TCP   │  Шлюз агентов (AgentGateway)       │
 │  • работает в фоне, значок в     │◄──────►│    порт 45800, JSON-кадры          │
 │    трее, автозапуск при входе    │ 45800  │                                    │
 │  • снимок экрана по расписанию   │        │  Реестр клиентов (ClientRegistry)  │
 │    и по команде оператора        │        │  REST API + веб-панель (5080)      │
 │  • активное окно, бездействие,   │        │  ┌──────────────────────────────┐  │
 │    CPU, ОЗУ, версия, IP, домен   │        │  │ список сотрудников, снимки,  │  │
 └──────────────────────────────────┘        │  │ запрос снимка, автообновление│  │
                                             │  └──────────────────────────────┘  │
                                             └────────────────────────────────────┘
```

## Возможности

| Требование задания | Реализация |
| --- | --- |
| Клиент под Windows на C# | `src/EmployeeMonitoring.Client` — .NET 10, WinForms, `net10.0-windows` |
| Автоматический запуск при входе пользователя | ключ реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (команда `--install`), плюс поддержка планировщика задач и GPO |
| Работа в фоновом режиме | значок в области уведомлений, контекстное меню, окно состояния, отсутствие окон и терминала (`WinExe`) |
| Связь с сервером по любому протоколу | собственный бинарный протокол поверх TCP (порт 45800), длина кадра + JSON, без сторонних библиотек |
| Список подключённых клиентов: домен / компьютер / IP / пользователь | таблица веб-панели + `GET /api/clients` |
| Время последней активности клиента | «последняя связь» (время heartbeat), время бездействия, активное окно и процесс, метка времени последнего снимка |
| Получение скриншота рабочего стола | периодический снимок по расписанию + кнопка «Снимок» в панели (команда по TCP), просмотр в панели |
| Сервер на любом языке, веб-интерфейс | ASP.NET Core (C#), веб-панель на HTML/CSS/JS без единой внешней библиотеки |
| Без сторонних библиотек | только BCL и Microsoft: `System.Text.Json`, `System.Drawing`, `System.Net.Sockets`, `Microsoft.AspNetCore.App` |

Дополнительно: токен доступа агентов, Basic-аутентификация панели, журнал событий,
автоматические уведомления о снятии снимка, ограничение частоты команд, режим «экран заблокирован».

## Требования

* **Сервер:** .NET 10 SDK (или .NET 10 Runtime для запуска). Windows, Linux или macOS.
* **Клиент:** Windows 10/11 (x64/arm64), .NET 10 Desktop Runtime (или self-contained сборка).
* Сторонние NuGet-пакеты не используются: восстановление пакетов не требуется,
  `dotnet restore` работает без доступа в интернет.

## Сборка и запуск

### 1. Сервер

```bash
dotnet build EmployeeMonitoring.sln -c Release
dotnet run --project src/EmployeeMonitoring.Server          # http://localhost:5080
```

Панель оператора: **http://localhost:5080/**
Шлюз агентов: **TCP 45800**

> Панель нужно открывать **по адресу `http://localhost:5080/`**, а не двойным кликом по
> `index.html`. Браузер запрещает запросы к серверу со страниц, открытых по протоколу
> `file://`, поэтому список клиентов останется пустым. Если открыть файл напрямую,
> панель покажет красную подсказку с правильным адресом.

Готовые исполняемые файлы (для копирования на сервер):

```bash
dotnet publish src/EmployeeMonitoring.Server -c Release -r win-x64 --self-contained false -o artifacts/server
```

Корень веб-приложения задаётся явно (`AppContext.BaseDirectory`), поэтому сервер
запускается из любого каталога, из планировщика задач и из службы.

### 2. Агент на рабочем месте

```bash
# разовый запуск для проверки связи (подключается, шлёт снимок, выходит)
EmployeeMonitoring.Client.exe --server 192.168.1.10 --port 45800 --capture-once

# обычный запуск в фоне (значок в трее)
EmployeeMonitoring.Client.exe --server 192.168.1.10

# включить автозапуск и завершить работу
EmployeeMonitoring.Client.exe --install
```

Ключи командной строки:

| Ключ | Назначение |
| --- | --- |
| `--server <host>` | адрес сервера |
| `--port <number>` | порт сервера (по умолчанию 45800) |
| `--token <value>` | общий токен доступа |
| `--config <path>` | путь к файлу конфигурации |
| `--capture-once` | разовый снимок и выход (удобно для планировщика задач) |
| `--install` / `--uninstall` | включить/отключить автозапуск |
| `--no-autostart` | запуск без включения автозапуска |
| `--help` | справка |

### 3. Автозапуск при входе пользователя

Основной механизм — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
(не требует прав администратора, применяется на пользователя):

```bash
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v EmployeeMonitoringAgent /t REG_SZ /d "\"C:\Program Files\EmployeeMonitoring\EmployeeMonitoring.Client.exe\"" /f
```

Альтернативы для развёртывания в организации:

* **Планировщик задач:** `schtasks /create /tn "Мониторинг трудовой активности" /sc onlogon /rl limited /tr "\"...\EmployeeMonitoring.Client.exe\""` —
  вариант `--capture-once` выполняет только снимок по расписанию, а не постоянный фоновый процесс.
* **GPO / Intune:** развернуть MSI/EXE через `Computer Configuration → Scripts`,
  передать `--server` и `--token` ключами или через файл `appsettings.json` рядом с EXE.

Значок в трее и уведомление при каждом снимке — агент работает прозрачно для пользователя,
это осознанное требование к корректному развёртыванию (см. «Правовые аспекты»).

### 4. Брандмауэр Windows

Сервер слушает TCP 45800 (агенты) и HTTP 5080 (панель). Разрешить порты один раз:

```powershell
New-NetFirewallRule -DisplayName "Employee Monitoring Agent (TCP 45800)" -Direction Inbound -Protocol TCP -LocalPort 45800 -Action Allow
New-NetFirewallRule -DisplayName "Employee Monitoring Dashboard (HTTP 5080)" -Direction Inbound -Protocol TCP -LocalPort 5080 -Action Allow
```

## Настройка

### Сервер — `src/EmployeeMonitoring.Server/appsettings.json`

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `urls` | `http://0.0.0.0:5080` | адрес веб-панели |
| `Agent:Port` | `45800` | TCP-порт для агентов |
| `Agent:HeartbeatSeconds` | `15` | как часто агент шлёт состояние |
| `Agent:CaptureIntervalSeconds` | `60` | период снимков экрана |
| `Agent:RequireToken` / `Agent:Token` | `false` / `""` | требовать общий токен |
| `Agent:OfflineAfterSeconds` | `60` | после какой тишины агент считается отключённым |
| `Dashboard:RequireAuthorization` | `false` | Basic-авторизация панели |
| `Dashboard:UserName` / `Dashboard:Password` | `admin` / `""` | учётные данные панели |

Любой параметр переопределяется переменной окружения, например:
`$env:Agent__CaptureIntervalSeconds="15"`, `setx Dashboard__Password="..."`.

### Агент — `appsettings.json`

Файл рядом с EXE (при первом запуске в него записывается `ClientId`); если EXE установлен
в папку, доступную только для чтения, конфигурация автоматически переносится в
`%LOCALAPPDATA%\EmployeeMonitoring\appsettings.json`.

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `ServerHost` / `ServerPort` | `127.0.0.1` / `45800` | адрес сервера |
| `Token` | `""` | общий токен доступа |
| `ClientId` | `""` | идентификатор агента (заполняется автоматически) |
| `HeartbeatSeconds` | `15` | период heartbeat (фактическое значение задаёт сервер) |
| `CaptureIntervalSeconds` | `60` | период снимков (фактическое значение задаёт сервер) |
| `MaxScreenshotWidth` | `1600` | ширина снимка, большие экраны уменьшаются |
| `JpegQuality` | `60` | качество JPEG (10–100) |
| `CaptureOnStart` | `true` | снимок сразу после подключения |
| `StartWithWindows` | `true` | включить автозапуск при первом запуске |
| `ShowTrayNotifications` | `true` | уведомлять пользователя о снимках |
| `ReconnectMinSeconds` / `ReconnectMaxSeconds` | `2` / `30` | переподключение с растущей паузой |

Журнал работы агента: `%LOCALAPPDATA%\EmployeeMonitoring\logs\agent-ГГГГММДД.log`.

## Протокол

Собственный бинарный формат поверх TCP без сторонних библиотек.
Кадр: **1 байт — тип**, **4 байта — длина (int32, big-endian)**, **payload**.
Сообщения — JSON в UTF-8 (System.Text.Json), изображение — «сырые» байты JPEG.
Максимальный размер кадра — 16 МБ.

| Тип | Направление | Payload |
| --- | --- | --- |
| `Auth` (1) | агент → сервер | компьютер, домен, пользователь, IP, ОС, версия, MAC, число мониторов, токен |
| `AuthResult` (2) | сервер → агент | результат, интервалы heartbeat и снимков, имя сервера |
| `Heartbeat` (3) | агент → сервер | бездействие, активное окно, процесс, CPU, ОЗУ, время работы, статус |
| `Command` (4) | сервер → агент | `captureScreenshot`, `ping`, `showNotification`, `shutdown` |
| `ScreenshotMeta` (5) | агент → сервер | время съёмки, разрешение, размер, признак блокировки экрана |
| `ScreenshotData` (6) | агент → сервер | байты JPEG |
| `CommandAck` (7) | агент → сервер | подтверждение выполнения команды |
| `Log` (8) | агент → сервер | предупреждения агента (например, ошибка снимка) |

Ограничения на стороне сервера: максимум 30 команд в секунду на агента,
таймаут рукопожатия 15 секунд, проверка токена при подключении.

### Обрыв связи и переподключение

Соединение считается живым, только если по сокету идёт обмен. Для надёжности применяются:

* **TCP keepalive** на сокете агента: 10 секунд простоя, 3 попытки с интервалом 5 секунд;
* **сторож сессии**: если по соединению нет обмена дольше `2 × интервал heartbeat + 10 с`,
  сессия принудительно закрывается;
* сессия завершается **по первому завершившемуся циклу**, поэтому зависшее чтение
  из сокета не блокирует переподключение (сокет закрывается до ожидания потоков);
* повтор подключения с растущей паузой (`ReconnectMinSeconds`…`ReconnectMaxSeconds`),
  все попытки записываются в журнал агента;
* аналогичный сторож на сервере закрывает соединение, если агент перестал присылать данные.

## HTTP API панели

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | состояние сервера и количество подключений |
| `GET /api/clients` | список агентов: компьютер, домен, пользователь, IP, активность, снимок |
| `GET /api/clients/{id}` | подробности об одном агенте |
| `GET /api/clients/{id}/screenshot` | последний снимок (`image/jpeg`, поддерживает `ETag`/`304`) |
| `POST /api/clients/{id}/command` | команда агенту: `{"action":"captureScreenshot"}` |
| `DELETE /api/clients/{id}` | удалить агента из списка |

Панель сама обновляет данные каждые 5 секунд (интервал настраивается), поддерживает
поиск, фильтр «только активные», просмотр снимка во весь экран и историю отключений.

## Правовые аспекты и этика

Скрытый контроль действий сотрудников без уведомления нарушает законодательство
большинства стран (в России — ст. 137, 138 УК РФ, ФЗ-152; в ЕС — GDPR, вплоть до
запрета на мониторинг рабочих мест). Поэтому в проекте заложены прозрачные настройки
по умолчанию:

* агент всегда показывает значок в трее и уведомление при каждом снимке;
* агент запускается от имени пользователя и не скрывает процесс;
* в комплекте нет средств обхода контроля и сокрытия активности;
* перед развёртыванием необходимо уведомить сотрудников и получить их согласие,
  а также зафиксировать регламент и сроки хранения снимков.

Для законного применения в тестовых стендах используйте отдельные виртуальные машины
или собственный компьютер.

## Возможные проблемы

| Симптом | Причина и решение |
| --- | --- |
| Панель открыта как локальный файл и список пуст | открывайте по адресу `http://localhost:5080/` (не двойным кликом по `index.html`) |
| Агент не появляется в панели | проверить порт 45800 в брандмауэре, `Agent:Port`, значение `ServerHost`; журнал агента — `%LOCALAPPDATA%\EmployeeMonitoring\logs` |
| Агент в журнале пишет «Повтор подключения» | сервер не запущен или недоступен; агент подключится сам, либо поднимите сервер и обновите панель |
| «Неверный токен доступа» | значения `Agent:Token` на сервере и `Token` у агента должны совпадать |
| `Не удалось занять TCP-порт 45800` | порт уже занят другим экземпляром сервера; изменить `Agent:Port` |
| Панель открывается по `localhost`, но не по IP | `urls` должен быть `http://0.0.0.0:5080` и разрешён в брандмауэре |
| «Снимок не получен» | агент ещё не снимал экран, либо рабочий стол заблокирован (изображение не передаётся) |
| Две копии агента | вторая копия сообщает об ошибке: используется блокировка файла в `%LOCALAPPDATA%\EmployeeMonitoring` |
| Панель возвращает 401 | включена `Dashboard:RequireAuthorization` — введите логин и пароль |
